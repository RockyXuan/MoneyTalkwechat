## 这轮实现了什么

1. 复用既有 **Zod、统一金额/引用/分类验证**，添加实验性的紧凑传输协议。项目身份和单笔空结构由程序生成，不要求模型逐笔重复；金额仍由真实操作数计算，不猜币种、价格、新分类身份或循环起始月。协议 version=2 先严格解析，再转为原规范；不修复残缺 JSON、不执行模型代码、不创建账目。
2. 日期校验增加简单事实核算：昨天/前天必须符合日期锚点；只说月份不能被填成某日；中文月份、明确年月和 ISO 日期核对原引文。复杂范围和未能证明的日期含义加待核对说明，不能把此有限校验当作全语义证明。
3. 免费套餐证据在每题前复查有效期，不因长批次把一小时的观察当永久授权。UTC 日预算、单实例锁、未知结果保持预留、不自动重试和凭据禁日志继续保留。
4. 添加 `messy-cases.json` **4 组人工虚构题**（约 1,000 / 2,100 / 6,200 / 1,000 字），覆盖跨平台、分类切换、长距离更正、实付/邮费、同额独立订单、中文数字、未知价格、新分类二选一、未知循环起始月和没有分类标题时按用途推断分类。逐项人工预期与金额汇总互核。**这些长段题尚未调用模型，不能算通过；文字长度也不等于已验证某分钟的真实口述。**
5. 原有 8,000/20,000/50,000 字、80/400 项规模题继续保留。显式 `--extended` 才允许选择，按输出容量预留；超上下文/免费预算即在发送前阻止，原文不截断。400 项的完整原协议可能超单日免费预算，后续须验证任务分段与跨段校对，当前不承诺已支持。

准备模块均未被 `src/` 或 `worker/` 导入。未新增依赖、模型权重、第三方 SDK、AI binding、数据库迁移或云端写入。

## 为什么推理现在停在预算保护

本机刚过午夜仍是 UTC 2026-10-13。Cloudflare 官方每日 10,000 免费单位在 **00:00 UTC，即北京时间 08:00** 重置。2026-10-13 的旧评测仍计入此次窗口，不能按本地日期宣称额度重置。

实际 Free 状态重新核实后，本地评测预留上限从上一轮的 8,000 调为 **9,500**，仍留 500 余量；这不是付费上限，也不保证其他项目没有使用共同额度。每次按输入 UTF-8 字节高估与输出上限预留，已结束且有合法 usage 才保守结算。当前 8,688.004 加下一短题的最坏预留约 1,246，超过 9,500，调用前停止。**没有声称整个账户 10,000 已耗尽。** 不通过反复改上限、截断原文、放宽检查或付费继续制造完成。

剩余额度窗口是外部约束；离线协议、完整校验、长段题、回归及文档已继续执行，不需要用户重复批准。此轮未建立定时任务或后台推理进程，不能承诺结束回复后会自动调用模型。
