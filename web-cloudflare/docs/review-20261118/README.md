# MoneyTalk 全站复审与分批改造方案

## 审查口径

2026-11-18，分支 codex/html-cloudflare-restart，起点提交 6d5efc3 加当前未提交功能。最新订阅、日历、消费对象进度包含未跟踪文件，单独检出提交不能重建当前网页。以下缺陷以当前工作区为准。个人长期记账优先考虑中断后接着记、金额准确、已保存结果可信和数据可恢复。

## 本轮直接处理

| 使用场景 | 原问题与影响 | 修改及可重复检查 |
| --- | --- | --- |
| 登录过期后导出账单 | 导出允许任意成功响应，登录页可能被下载为 CSV，显示成功 | 核对服务端实际返回的 text/csv。用 200 HTML 和正常 CSV 各测一次 |
| 打开账单或统计时订阅服务故障 | 所有页面先调用续记，只要这个请求失败，其余数据就不读取 | 续记暂不可用时继续读取已保存账目，在页首保留警示。认证拒绝仍走错误流程。订阅测试覆盖失败、刷新恢复 |
| 退出后订阅或来源表单有待重试内容 | 退出清理普通草稿和口述缓存时遗漏 pending-module，可能在同一会话再次出现 | 退出时清理这个应用的待重试表单。保留显示偏好，在原退出／重登录用例增加检查 |
| 页面跳转及标题 | 页面名重复维护，增加页面时可能出现菜单可点而地址失效 | 地址合法性与浏览器标题共用已有导航清单。主要任务和错误提示占据页首，移除五个页面共用的宣传副标题 |

## 再改什么，怎样验收

| 顺序 | 改动与依据 | 完成条件 |
| --- | --- | --- |
| 1 订阅队列 | worker/recurring-subscriptions.js 每次只处理五批；超过 120 笔及分类全失效的规则都可能占名额却不更新排序。连续五个这样的历史规则可能长期挡住后面的正常订阅。属于代码推演，线上发生率未知 | 临时账本创建五组需人工处理及第六组正常规则，连续两轮仍能处理正常项，逐项提示问题且不重复。用有界分页或持久游标保证前进，实测每轮 D1 查询预算 |
| 2 切换账本 | src/app.js 的 activateLedger 分几次切换请求目标和界面数据，旧 recent、textSummary、stats 可能跨越重新渲染。需要慢网络复现 | 两本虚构账分别用明显不同的标题，逐段延迟或中断请求，检查切换、快速返回、重试时从未显示错账本。读齐新会话后一次更新状态，阻止切换途中操作 |
| 3 录入与续记 | recordPage 已把输入框放在首位。用户最常中断的步骤是口述完若干笔后查看原平台，回来找下一笔 | 从三个样稿选布局；实际页面接回现有草稿、进度与逐笔确认。360/390/430 像素和桌面下检查键盘弹起、刷新、跳着确认和草稿恢复，首尾商品、缺口、下一笔始终可到达 |
| 4 账单与统计 | 现有单字段编辑、月份精度及筛选后导出已经有实际用例。统计分类和账单列表共享账本口径 | 先锁定同一虚构账本的月／季／年合计、未指定日、修改、删除与撤销结果，再调整布局。筛选后的条数、金额和 CSV 可对上 |
| 5 订阅页 | 卡片同时展示周期金额、累计金额、选色、月份、来源、调整及状态，11 行源码里包含整页、表单和多数分支 | 把金额摘要、状态与月份详情拆成可读函数。保留 30 元预填、实际已记合计和停用入口。合成月付／年付各走新建、暂停、恢复、改金额及删除某月 |
| 6 设置与恢复 | 已有独立候选账本、内容指纹及分块导入，适合继续复用。失败后用户最关心原账本和下一步 | 分块中断、同一备份重试、旧版本、合计核对、切换前取消全部通过。按钮处能读到当前账本与候选账本名称 |
| 7 代码边界 | app.js 同时承担路由、弹框、保存、恢复、图表和焦点管理。render 中特意保留正在输入以及手指按住的节点，整体替换容易让 WebKit 丢点击 | 先分离备份流程，再分离页面加载。一次移动一条用户流程；做行为等价测试。渲染与焦点管理最后处理，保留连续输入和双击防穿透测试 |

## 分工与发布

主负责人冻结当前工作区差异，审核跨账本、金额、日期和权限边界。第一批可并行分配订阅调度与首页样式，各自只改独立模块和对应测试。涉及 app.js 的导航、加载、切换账本串行集成。子任务交付包含实际差异、失败复现、修复后读回和未测项，由主负责人独立核对。实际模型与推理强度需从运行信息确认，本轮未委派。

每批先跑针对性反例，再执行 pnpm verify:release。发布前保存拟发布源码和上一个可回退版本，核对新增迁移是否已应用。批准的合成账本完成写入、刷新、撤销、清理后，分别记录线上版本、真实手机及国内网络情况。缺少线上读回时，只报告本地验证。

## 界面样稿

打开同目录 demo.html，切换 A／B／C。A 单栏输入优先，B 上次进度优先，C 桌面左侧输入、右侧续记。小屏顺序随布局变化。示例只用固定的午餐和收纳盒，按钮演示候选与进度展开。日历、统计和设置的最终视觉验收仍应使用实际页面。

## 复用依据

保留项目现有原生页面、Cloudflare 服务、身份校验、已确认账目和浏览器测试；本轮未新增依赖。下载检查使用浏览器已有响应类型。对照了 [MDN Fetch 文档](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch)、[Cloudflare D1 容量限制](https://developers.cloudflare.com/d1/platform/limits/) 及 [Actual Budget 源码仓库](https://github.com/actualbudget/actual)。Actual 采用本地优先架构，迁入其同步层会改变本项目的数据来源和隐私边界，本轮未引入其代码。

## 实施切片

- 订阅页已抽出单卡渲染，列表和单卡分别维护。下一次调整金额或操作按钮从 subscriptionCard 进入，表单沿用 subscriptionForm。导航标签的路径白名单与浏览器标题也已合并。
- 记账、账单、统计、订阅和设置都在同一应用内。切换账本和站内标签必须分别覆盖，前者改变数据来源，后者仅改变显示位置。
- 测试目录中的 acceptance-screenshots 有 10 月 3 日的历史截图；其中记一笔仍只有四个底部入口。评审当前主流程应使用本轮双引擎结果及其附件，避免按旧截图改回旧首页。
- 首页落地时保留“保存并解析”、真实云端草稿读回和绿色逐笔确认。demo 的“预览示例”只演示布局；顶部 A/B/C 按钮只用于选方案。视觉配色服从账目语义，不能用装饰绿色把未完成的进度画成已确认。
- 确认首页后，先在手机加载键盘时比较输入框、保存按钮、最近对象和继续位置，再在桌面检查同屏输入和核对。分别记录一次无中断录入和一次切换来源后继续的点击数，以现有网页实测作为对照。

## 架构取舍与核对边界

| 环节 | 当前依据 | 改造时必须保留 |
| --- | --- | --- |
| 身份与账本 | worker/auth.js 校验令牌签发方、接收方、有效期以及拥有者邮箱；本地预览同时要求开发标记与回环地址 | 服务端决定可读写的账本。个人与家人权限另立需求，不能以放松现有验证实现 |
| 金额与日期 | shared/format.js 先用整数处理分，再校验范围；月份和确切日期均可保存 | 金额输入、合计和 CSV 使用同一精度；只说月份就显示月份 |
| 保存与重试 | worker/store.js 以用户、账本、操作标识查找既有结果，校验请求内容 | 同一次请求只记一次；另一次相同金额的真实消费可独立入账 |
| 导出与恢复 | CSV 用于阅读，完整 JSON 包含恢复所需的身份和关联信息。worker/restores.js 分片写入后复核条数和内容指纹 | 先核对独立账本再切换；用户看得到有效账目、回收站与金额合计 |
| 页面与数据 | 现有 views 展示、shared 业务规则、worker 权限与写入三层可继续使用。订阅是横跨三层的实际例子 | 页面解释状态，服务端核对事实，共享模块计算金额／日期；不在每个页面各算一次 |

## 用户已选定的首页

手机用 A，电脑用 C。实际记账页保留现有大输入框和同页候选卡；手机先录入、再看进度，1100 像素及以上桌面把录入与消费对象进度置于同一行。中间宽度沿用原有平板布局。保留真实账单的语义色，主输入卡及“保存并解析”采用深绿色。对照用例检查两张卡的实际坐标、同一份输入和截图；首页样稿的三个选项只在本地比较页出现。

## 第二批执行记录

- 订阅检查一次读取本轮账本的有效分类，只有确实要写入的批次才占每轮五批的名额。隔离数据库用连续五条分类已停用的规则和一条有效规则验证，一轮返回五条待核对提示并写入一笔正常订阅。再次检查新增零笔，金额合计与预期一致。沿用每次最多读取 500 批的上限，超出该扫描范围的多账本调度未在本次验证。
- 切换成功后重新从服务端打开当前页面，原账本的数据与页面操作一起退场。新账本按身份和账本读自己的草稿。用两个合成账本延迟新会话响应，等待期间只有加载画面；恢复后显示正确的账本名，切回原账本也能读回。
- 页面并行读取和分批恢复备份移入 src/ledger-data.js。主页面仍负责显示进度、错误与重试。完整恢复必须完成最后的云端校验才显示切换按钮。无数据表变更。

中间两轮 WebKit 的站内标签测试记录到离开页面后的读取报错，各轮 285/286 通过。补上订阅内容已经显示的断言、在页面切换或退出时取消旧读取，并在浏览器后退恢复页面时重新读取。修正后 WebKit 快速切换、刷新、关闭及重开标签的定向场景连续三次通过。未关闭浏览器报错检查。

随后一轮全站测试的站内标签已通过，WebKit 取消日期筛选并马上离开页面的用例报告读取中断（285/286）。补查取消日期范围后的实际筛选标签数与结果条数，两个目标宽度各自通过。上线前旧版本从部署列表读回为 0c6ee53e-fb40-42ca-8799-5f90a117d6a4，占 100% 流量。
