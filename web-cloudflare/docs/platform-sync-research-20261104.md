# 平台消费自动同步：调研与分阶段计划（2026-11-04）

## 本次授权与目标

用户重新授权调查淘宝、拼多多、京东、抖音、建行、Steam、滴滴等平台接入方式，仅做研究与计划。旧封存范围不因此进入实现，moneytalk 定时任务继续暂停。

本次已确认：优先取得实际支付记录；最好全自动，允许偶尔重新登录。消费按购买时的整笔金额记录，后续偿还本金不重复计消费。自动取得记录、整理分类后由用户确认入账，不自动写入正式账本。优先平台、建行卡种、可否用 Mac 常驻程序仍待用户回答。历史资料中的手机、月付偏好仅作背景，不替代本次确认。

成功标准：持续取得本人授权范围内的消费变化，明确覆盖期间和缺口；同一消费不因订单、支付平台和银行三份证据重复记账；登录失效和漏采可见；保护手录数据，可撤销。自动取得记录与正式入账分开，只有用户确认后才生成正式账目。

## 调查结论及证据等级

公开文档调研，没有登录平台控制台、申请权限、调用交易接口或读取真实记录。官方接口存在不等于个人可申请，官方文档可读不等于线上接口有效。未发现可直接供本项目采用的跨平台个人消费聚合 API。

## 怎样接近全自动

1. 官方个人只读授权 API：优先。有增量查询或事件推送、刷新授权时，才有机会持续后台同步。每个平台先证实申请资格和可用权限，不为了拿商户接口注册不相符业务。
2. 官方自动发送的电子账单/收据：若平台确有订阅，且用户选择专门收件范围，可自动取件与解析。只证明一封收据可取不能证明历史完整；每个平台是否订阅、发送频率、退款是否覆盖仍需核实。不得默认访问整箱邮件。
3. Mac 上的本人会话辅助读取：仅作候选。购物网站如果允许且数据可读，可调查专用浏览器会话或最小权限扩展；账号验证由用户完成，Cookie 不上传云端。登录过期、验证码、页面改版、反自动化及 Mac 睡眠都可能中断，必须显示中断，不能承诺无人值守。银行与支付账户不交给浏览器代理操作，流水通过官方只读授权或用户手动取得文件。
4. 手机通知/短信辅助：只适合及时生成候选，存在不发送通知、合并通知、只显示部分金额和退款漏报；不能代替完整账单。iPhone 的实际可用系统能力需要另查，不照搬 Android Hook/Root 方案。
5. 用户导出文件后自动处理：可靠的兜底和对账途径，但不满足全自动取数目标。不得用“支持导入”冒充“已支持自动同步”。

建议采用组合：支付流水覆盖金额，购物订单补名称/分类，定期完整账单补漏。先选一个确实可自动获取的来源做闭环；若第一来源都只能手动导出，明确报告达不到全自动，而非先开发大量导入功能。

## 产品规则：先避免金额失真

- 来源原始记录与正式账目分开。来源内以账号、平台、交易号及事件类型识别重试；跨平台凭明确支付号/订单关系合并证据。仅同额同日进入待核对，不删除两次独立消费。
- 已入账后再同步，不能覆盖用户改过的分类/备注，不能复活用户删除的记录。
- 购物平台与支付平台不同：例如拼多多购物用微信支付，界面分别保存购物来源、支付渠道，不能混成一个平台字段。
- 退款、本金还款、充值、钱包消费是不同事件。同步先保留事实，不自行恢复此前暂缓的退款专项，也不把退款默认为工资等收入。
- 用户明确选择：白条购买1200元商品时记录1200元消费，后续每月偿还100元本金不再计支出；利息与手续费只有取得真实明细后才单独核对。只取得还款流水而缺原购买记录时标记缺口，不凭还款反推购买日期或虚构整笔消费。Steam充值与钱包消费同样须避免重复，但其具体来源对应规则仍需验证；本次不扩展完整资产管理。
- 页面展示最后成功获取时间、实际覆盖期间、来源状态和待核对数量；无法确认完整覆盖时不显示“已同步全部消费”。

## 阶段计划与退出条件

| 阶段 | 交付 | 完成标准 |
| --- | --- | --- |
| A：资格核实（仍属调研） | 优先三个来源的官方接口申请条件、费用、授权字段、续期/历史范围清单；淘宝买家接口优先追查 | 每个来源明确可申请/需平台确认/无法证实，避免把文档存在当获准接入；无需账号密码 |
| B：选自动化路线（仍属计划） | 每个优先来源选择 API、订阅、Mac 辅助或仅手动兜底，列用户操作和失败条件 | 明确是否真的自动取数；确认执行设备、数据接收方；遵守整笔消费不重复计本金和用户确认入账的已选规则 |
| C：独立只读试验（需用户后续授权） | 一个来源、固定时间范围，读到隔离候选区，不碰正式账本 | 用户本人完成登录/安全确认；取数条数金额可核对，重复拉取不重复，中断可恢复 |
| D：MoneyTalk 候选同步（需后续开发） | 自动取数→分类建议→确认，已有手录可继续；所有授权可撤销 | 完成权限、并发、重复、金额、恢复集成测试及 Chromium/WebKit E2E，完整发布门禁通过 |
| E：持续运行观察 | 两个自然同步周期＋完整账单补漏对照 | 无未解释金额差异；Mac 离线、登录到期、退款延后和跨平台重复均有明确表现；正式入账始终保留用户确认 |

## 对抗性验收清单

重叠时间段、同文件多次、同额独立消费、订单合单/拆单、部分退款/跨月退款、平台余额/银行卡混合支付、外币及汇率未知、长交易号、分页中途新增、凭证到期、超时但已取到、网络断开、Mac 睡眠、撤销授权、伪造上传身份、手改后重同步、删除后重同步、恢复备份再同步。未知记录进入待核对，金额逐分核算；来源只读凭据不能拥有账本删除权限。

本次验证仅为仓库状态与公开文档/开源资料检查，没有接口联调、集成/E2E运行、部署或真实设备验收，也没有证明任一平台已可全自动同步。
