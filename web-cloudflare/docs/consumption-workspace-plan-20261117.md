## 真实使用过程

用户拿手机对照原软件消费记录，按时间段语音转文字，可能只完成一个月或中途离开。再次进入 MoneyTalk 时，先看到选中对象/账号的上次记录位置，再回原软件定位接着说。支付用了银行卡、支付宝还是微信不作为日常必填项。

对象：淘宝、拼多多、京东、抖音（差不多轩生/张可乐爸爸）、山姆、英雄联盟、原神、绝区零、崩坏星穹铁道、Steam、转账（含建行）、滴滴、其他订阅软件、App Store、GPT、Claude、苹果云。转账用途届时由用户说明，未知不猜。

对象代表正在看的账单来源；App Store等来源与游戏/订阅实际对象可分别保留。识别同笔证据时不得新增第二笔消费，缺强关联仅提示待核对。

## 页面常态

手机显示最近使用对象快捷按钮与“更多”，选中对象展示其进度；电脑复用既有平台进度板。对象可新增、改名、停用，历史归属保留。抖音两账号各自续记。

进度常态只显示：本次目标时间范围、已说到的位置（日期/月份＋末件锚点）、已确认到的位置、下一待处理项与缺口数量，以及“接着记”操作。详细历史、首尾锚点和原话按需展开，不能为缩短页面删除。

“已说到”依赖原文顺序与实际保存；“已确认”依赖服务器保存的正式结果。下一待处理项来自尚未确认候选，不等于用户下一次应在原软件查看的日期。不得将两者混成一个百分比。

时间范围是目标；只有用户明确表示范围已全部核对，且已知缺口得到处理，才标记范围核对完成。没有具体日只保存月份，不猜某一天。同一天多笔时保留末件和原序；反向翻阅、日期不连续或跨账号切换不凭最大日期计算连续进度。

## 自然语言与确认

目标流程：选择对象/账号 → 输入时间范围与消费原话 → 识别候选及进度建议 → 用户核对、确认 → 保存后更新对应进度。跨平台、改口、未说完及已有手录重复均保留核对边界；不假装理解能力已上线。复用现有候选与进度能力，先核实现状再决定最小改动。

已确认的金额规则继续有效：购买时记整笔消费，偿还本金不重复计消费；自动整理后由用户确认入账。当前方案不授权自动采集、读取私人邮箱或启用付费模型。

## 渐进式披露（后续需求长期适用）

默认界面突出金额、位置、必要状态和主要操作，不铺满解释段落。短帮助电脑悬停显示、移走隐藏，同时支持点击与键盘；手机轻触显示，提供关闭方式。长说明点击展开。浮层可被实际阅读，不在指针移入帮助内容时立即消失；键盘可关闭。

缺字段、错误、重复风险、保存状态及丢失输入的风险不藏进帮助。必要提示仍紧邻确认/保存按钮，帮助不能挡住操作。

## 实施前复核与验收

先查当前组件、数据与备份能力，提出最小实现范围；涉及非简单功能再核实官方和开源复用。自由口述解析需独立质量验证，不能用格式拆分通过替代。后续开发须验证中断重开、刷新、跨月、同日多笔、倒序、跳项、跨账号、修改/删除后进度、服务端失败与重试、重复消费、备份恢复，以及手机轻触、电脑悬停、键盘操作。执行完整集成及双引擎端到端门禁后才可发布。


## 追加授权：日历与订阅区

用户在确认上述方案后明确要求直接实现：各来源有日历展示已记范围；日历完成后新增独立订阅区，记一笔与订阅页均可录入，支持往年前推月付/年付历史（例如两年月卡）。不需要再次索取例行实现许可；定时任务、平台自动采集和付费模型仍不恢复。

日历实现选择：全年12个月摘要，点月份展开日期。绿色仅来自用户明确标记的已核对范围；账目日期显示圆点，不能据首末账目推断中间全部完成。范围独立保存，可撤销，不增删账目；允许无消费但已核对的范围。未知日期的月账不造具体日。原有账目不被自动涂满整月。

订阅复用现有循环候选、确认与防重能力，不建立第二套账本。每月/每年表单生成草稿，用户确认才展开入账；历史可跨年，每次最多120笔，过长须缩小范围，未来不提前入账。已有文字循环记录也在订阅页显示；暂停、日期不明、已删和历史范围分别表达。当前不提供银行代扣管理或实际取消订阅服务。
