# 空白处关闭弹框：执行与验收（2026-10-11）

目标：手机轻触、电脑单击弹框外空白即可回到原页面；没有实质修改不打断，未保存修改不误丢。

## 复用与边界

- 复用现有原生 `dialog`、关闭动画、保存锁定和“继续编辑／放弃修改”，不引入组件包。
- 核对 [MDN dialog 官方资料](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog)：原生模态弹框默认不提供点外侧关闭。采用统一事件处理，经过现有保存保护，而非直接 `close()`；兼容项目测试中的 Chromium 与 WebKit。
- 只有按下与松开均在外侧且没有拖动才触发关闭；点内部留白、拖选文本、滑动滚动不关闭。
- 原分类、恢复原值、金额格式相同的修改不算实质变化；月／日精度确实变化需要保护。金额异常输入仍算变化。
- 编辑账目、分类、筛选、显示设置、备份选择均保护未保存内容。保护提示的外侧再次点击不能自动放弃，继续编辑恢复原表单与输入。
- 正在提交不能关闭；记账结果尚未核实时先保留重试标识。文字核对栏沿用现有会话草稿保存，关闭后再次打开可继续，不因此入账；电脑栏旁实际操作按钮保持可用。
- 双击第二下不能穿透到背后的账单／按钮；限制为同一点附近短时间，避免影响其他位置的正常下一步操作。

## 验收步骤

1. 新增端到端测试：电脑 1440px、手机 390px；四个字段关闭、改回原值、未保存继续／放弃、内部点击／拖动、双击、通用表单、提交锁与失败重试、文字草稿再打开。
2. 用隔离的本地 Worker/D1 验证没有意外写入，完整执行集成测试及两浏览器端到端发布门禁。
3. 固定浏览器上下文审阅界面与真实点击，截图核对保护提示。
4. 发布 Cloudflare；核对实际版本、静态资源、登录保护和线上关闭行为，只读核对真实账本未被改写。
