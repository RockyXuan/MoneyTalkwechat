# 平台记账进度板 · 2026-10-11

目标：分段对照购物或支付平台账单录入后，下一次立即知道已报范围、实际已记范围和待核对缺口。电脑左侧紧凑记账，右侧六个平台卡片；手机上方查看进度、下方操作。分类显示已入账记录的实际分类，不另建第二套账本。

复用现有文字批次、原序 items、云端 slots、逐项确认、直接编辑和备份协议。平台来源沿用已有“平台 · 商品”标题，不增加数据库、依赖或迁移。参考 [GOV.UK 多任务状态](https://design-system.service.gov.uk/patterns/complete-multiple-tasks/)的状态区分，以及 [W3C disclosure](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/)的展开/收起规则；只借鉴规则，不复制组件代码。现有原生按钮、details 和 CSS 满足需求，无新增许可证/维护/体积负担。

## 行为与默认

- 六块默认是淘宝、支付宝、微信、拼多多、京东、抖音；其他识别到的平台和口述记录追加卡片。未记录显示空态，平台卡不是平台全部消费的统计。
- 每个平台聚合全部已取得的批次，不再只截前六批。最近一批展示原序“首件 …… 尾件”，标明这是已报范围；实际已确认的首尾另列，连续边界和下一项单独展示。跳着确认、删除、暂停、未纳入项目、旧批次未完成均明确提示。
- 按实际记录/建立时间展示批次，而非商品消费日期；原商品顺序不排序、不假设前后日期，也不补造精确日期。混合批次按各项来源拆到对应卡，但打开后仍是原批次，只写一份数据；来源证据不足保留口述记录。
- 卡片展示实际已记分类、保留颜色和数量；以 slots 对应账目的当前分类为准，改分类和删除后刷新跟随。名称过长换行显示，不仅靠颜色说明状态。
- 继续核对直接打开该平台最新待处理批次；记录一批直接打开输入并选定平台。核对前的来源按钮平铺，复用标题前缀保存，显式不同平台条目不被覆盖。
- 未保存会话草稿按平台保留，另有原来的通用文字草稿；切换到另一平台不会覆盖上一平台输入。已保存批次仍由云端列表继续，未保存草稿不计入云端进度。
- 历史批次可展开全部，不能把其他平台的更新遮住旧进度。平台聚合数据仍属于受保护当前账本；加载失败显示错误，不能显示“尚未记录”。
- 电脑根据剩余空间使用两列/三列；手机单列，不用横向拖动查看重要内容。动效使用现有确认退场和卡片状态过渡，减少动画偏好关闭动画，服务器确认后才更新进度。

## 验收门禁

先单元测试平台分组、混合来源、乱序确认、暂停/删除/跳过、旧批次与多批排序；集成测试从确认到进度、编辑分类、删除恢复、权限及完整备份恢复。两引擎 E2E 检查六平台、平台预选→解析→逐项保存→卡片刷新→继续、多批历史、长内容、手机/电脑布局及减少动画；保留旧功能全量回归。正式执行 pnpm verify:release，之后部署核对版本、资源和身份保护，用独立合成账本做线上读写回查并清理。真实 iPhone、国内网络、用户接受度单列，不用模拟冒充。

执行结果：本轮已实现并发布，75 项单元/集成、184 项双引擎 E2E、线上独立合成账本验证和清理均通过。具体版本、证据、修复过程及未验证边界见 [上线验收](platform-board-acceptance-20261011.md)。
