# 从研究到持续迭代的路线

研究不是一次性换皮。每个闭环分别固定用户任务、默认语义、可逆边界、异常用例和可见验收证据。调研只引用公开信息，不建立“最佳产品”权威排名。

## 现有问题与来源

| 长期痛点 | 证据层次 | MoneyTalk 对策与验收 |
|---|---|---|
| 连续记相似支出重复填字段 | iCost 模板、YNAB 官方复制文档 | 本轮独立复制草稿，默认本月；确认前不入账、主草稿不覆盖 |
| 找不到账，以为同步丢了 | Lunch Money 筛选能力＋本项目缺少搜索/类型摘要 | 本轮条件标签、单项清除与零结果说明；刷新保持条件 |
| 手机太长、平台进度难找到 | 本用户反馈＋三方案同数据对照 | 已选 B：固定平台按钮与一个完整详情，不去掉历史和首尾 |
| 待审核、已同步、已入账混淆 | Monarch 官方审核文档、Copilot 公开界面 | 保留真实服务器确认；操作处反馈；公开图不作为联调成功证据 |
| 口述有原价、实付、邮费，金额重复算 | 本用户真实场景；当前解析/候选代码 | 延续实付与邮费合计、原文保留、金额疑问不猜；新增语言样例逐条测试 |
| 改分类容易丢位置、熟悉入口跑位 | 一木商店历史评价＋本用户直接编辑要求 | 原有单字段编辑和保存高亮保留；平台顺序固定、颜色跟类别 |
| 退款误作收入，或跨月数字难解释 | [iCost 退款文档](https://help.icostapp.com/guide/claim/refund.html)、钱迹/Lunch Money 能力 | 用户已明确暂不做退款专项；收到口述时核对实际退款，不自动改真实旧账 |
| 白条/月付消费和还款算两遍 | 用户实际使用多；YNAB/钱迹转账与分期能力 | 候选方案画“购买→欠款→还款”关系，消费一次、本金还款不再算消费，手续费独立 |
| 银行/设备同步慢、重复导入 | [YNAB 官方重复记录排查](https://support.ynab.com/en_us/my-transactions-are-importing-more-than-once-ByyZUaPge)、iCost 同步排查、商店历史反馈 | 自动采集仍封存；保留幂等、操作结果查询和失败原输入。相似消费不直接删除 |
| 产品功能过多、打开慢、学习成本高 | MoneyWiz / Simplifi 历史评价与专业预算流程 | 首页只放常用任务；不增加银行账户、投资报表等无目标模块；用体积和实际渲染检查证明影响 |
| 长期批次增长，旧记录消失 | 当前代码明确 100 批上限、每批 10000 字、40 条确认选择 | 需要分页与历史归档设计。归档只能改变展示，不能删除原序、关联或真实账；本轮没有扩大接口上限 |
| 5–20 分钟口述杂乱，规则“越用越懂”的承诺不可信 | 用户场景与当前确定性解析范围 | 先聊天理解再核对；建立用户明确确认的私有规则与回归语料。通用大模型接入、成本和私密原文上传单独决定，不假称已自动学习 |

## 阶段 1：低摩擦基本任务（本轮）

交付：B 手机平台切换、筛选可见、回当前期间、再记一笔。

出口：集成与完整 Chromium/WebKit E2E；合成截图；实际服务发布版本；登录后受保护隔离账本写/读/清理；真机与用户验收单列。

## 已封存：退款专项

2026-10-12 用户明确“先不用管退款，有退款自己说”。因此不新增退款入口、关联模型或跨月统计选择。用户之后口述收到退款时，先拆出收到金额、对应商品与建议分类供核对，不把一笔退款自行归成工资，也不改写原消费或历史统计。

[退款草图](refund-choice.html)仅保留为研究参考，不是待审批任务，更不是已经实现的功能。未来只有用户重新提出相关目标时才恢复评估。

## 阶段 3：按用户选择加入预算或白条/月付

预算只需月度/分类额度，温和显示已用/剩余，不做未经请求的财务建议或打卡压力。验收覆盖无额度、超额、跨月和退款后的额度变化。

白条/月付先明确仅看消费还是同时看债务，再设计关系。本金还款不重复计消费；利息/手续费分别记支出；分期不得提前把所有未来付款塞进已发生账。验收比较全额支付与分期对相同商品的累计消费一致，并支持提前结清、退款和费用。

这两项不是默认全部上线。展示内容和计算含义先给可视化选择，再实现。

## 阶段 4：长期使用与输入规模

计划补齐已完成批次的分页、搜索和显示归档；本平台继续边界始终来自原顺序和实际账目，不用“最新六批”冒充全历史。大批次确认滚动、长备注、重复名称、跨平台混合和中途退出都要验证。保留未知状态，原文或关系缺失不能自动补齐。

必要时评估常用模板、隐私遮罩、PWA 主屏入口与轻量提醒。PWA 是网页安装入口，不等于新的 iOS 应用；离线仅保留草稿，必须服务器确认才显示入账。推送权限、隐私和行为偏好单独讨论。平台自动采集、投资、分享营销和复杂家庭权限不自动恢复。

## 持续 UI 验收规范

- 固定虚构账本、360/390/430/768/1440/1920 尺寸对比，不能用任意漂亮图片代替功能验证。
- 常用按钮至少 44px，输入文字至少 16px；空白关闭、未保存保护、键盘/底部安全区延续既有规则。
- 新页面一步只承载一个明确任务；推荐选项直接平铺，避免为两个候选打开下拉框。
- 反馈不抢焦点，必要错误靠近操作；加载失败与空数据不同；可读文字不只靠颜色。
- 过渡用于表示切换/保存结果，轻量 CSS 优先，不加动画依赖。检查减少动画、快速连续点击与返回后上下文。
- 每次上线都记录实际运行测试、部署版本、线上读回与未验证范围，并提供正常网页链接。
