## 证据边界

本轮阅读官方产品页、帮助文档、App Store 页面与公开用户评价，覆盖以下 17 个产品。公开网页设计与原生应用实际操作分开记录。没有购买付费产品、登录竞品私人账户或逐项真机体验；不能声称已经遍历它们的所有页面、动效和错误状态。

评分为本轮公开商店页面快照，地区分别标为 CN/US；商店可能显示缓存，不能作为实时榜单。评分数量不是用户数，累计下载不是月活。未发现可比较的独立留存率数据，因此不制作“全球最粘/用户最多”排名。历史评价用来提出检查假设，不证明现版本仍有该缺陷。

## 六个高价值经验

1. **把状态放在操作视野内。** 待处理、保存中、服务器确认和失败必须不同；文字候选仍由逐条确认产生真实记录。Monarch 的审核组织、Copilot 的待审核列表支持这一方向。
2. **筛选条件持续可见。** 查询为空常常是条件造成的，不应该让人误以为数据丢失。Lunch Money 的筛选能力和当前代码中遗漏搜索/类型提示，支持加入可单独取消的条件标签。
3. **重复输入复用记录。** iCost 模板和 YNAB 复制能力启发“再记一笔”；先复制到可改草稿，不能直接重复扣款。
4. **固定类别位置，颜色跟分类走。** 历史一木反馈与现有用户意见一致。排序变化不能让熟悉按钮跑位；颜色不跟排行变化。
5. **金额关系要解释清楚。** 支出、退款、还款、转账不是同一种收入支出；当前结余仍仅表示期间收入减支出。退款/白条月付需要关联模型，不能偷加“其他收入”凑统计。
6. **动画说明结果，而不是掩盖等待。** 沿用已有轻量 CSS 过渡和减少动画偏好；只在服务器确认后退场。[W3C 状态消息](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)要求结果可被辅助工具获知，不强抢焦点；项目触控目标 44px 高于[WCAG 2.2 最小目标 24px](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。未逐款录制原生动画，不宣称竞品时长已实测。

## 功能候选与优先级

| 顺序 | 内容 | 是否本轮直接做 | 原因/决定边界 |
|---|---|---|---|
| 1 | 可取消的筛选标签、当前月份快捷返回 | 是 | 不改变账目与个人偏好；直接减少误解和点击 |
| 2 | 复制已有记录为新草稿 | 是 | 金额/分类/备注可复用，当前月份默认，不偷偷入账、不覆盖主草稿 |
| 3 | 手机六平台快捷切换 | 用户已选 B | 六个平台状态总览＋选中平台完整进度；桌面保持铺开 |
| 4 | 退款关联原消费（部分、多次、跨月） | 用户明确封存 | 2026-10-12 暂不做专项；有退款由用户口述再核对，真实历史不自动重算 |
| 5 | 预算/分类额度与温和提醒 | 偏好待讨论 | 用户是否想控制花费，还是只记录？不擅自加压力型目标 |
| 6 | 白条/月付的消费与还款关系 | 后续具体设计 | 用户实际使用多；要避免消费＋还款算两次，需明确账本范围 |
| 7 | 手机隐私遮罩、常用模板、搜索最近条件 | 下一轮可逆候选 | 先证明收益；不增加空入口或记账额外步骤 |
| 8 | 家庭共享、多币种、票据、复杂分拆 | 暂不首版强制 | 数据/权限/隐私和复杂度成本，不因竞品有就上线 |

三大原则：按可完成任务验收；只解决用户场景中的必要问题；主动验证筛选零结果、重复复制、未保存内容、停用分类、断网、权限和回归。研究沉淀后仍须完整集成＋双浏览器 E2E 门禁。
