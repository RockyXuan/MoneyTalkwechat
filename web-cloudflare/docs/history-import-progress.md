# 历史账单接入：当前可用能力与下一道验证

更新：2026-10-02。用户已确认白条、美团月付、抖音月付均常用；历史批量处理优先，近期手录，默认每月核对。持续推进规则见根目录 AGENTS.md。本文记录实际实现，不把调研中的候选能力写成已接通。

## 已实现

- “我的 → 历史账单核对”：一次选择多份原始文件，来源账户标记、候选金额、退款证据、未拆清还款、来源缺口、异常行、分页及只看待核对、下载 JSON 报告。
- 根据上游已公开的字段格式适配支付宝手机 CSV、微信 CSV，自动处理 UTF-8/BOM、GB18030、UTF-16LE；表头可重排，长交易号保持字符串，金额复用项目整数分规则。
- 包含 CSV 的 ZIP 自动解压：支持 AES／传统 ZipCrypto；每份包可输入独立解压码，用后清除；错误码可在同批文件上重试，无需重新找文件。
- 来源交易号相同且内容一致的证据去重；同号不同金额／日期／状态标为冲突；同日同额同商户只列疑似，不删除或自动合并。
- 白条／两种月付还款进入待核对，不当作新消费，也不把未拆分费用的整笔还款假定为本金。退款不转成普通收入；已退款支付行保留原金额和待核对说明。
- 本机 `pnpm bills:review` 生成私有原件副本与报告，只写全新目录、完成标记最后生成；禁止输出到 Git 跟踪目录。浏览器处理不上传原件、解压码或候选账目，不访问支付平台、邮箱、第三方 AI。

此版本是只读核对工具，没有“写入正式账本”按钮。没有匹配已有手录，也没有完成月付消费明细接入、自动邮件下载、订单采集或聊天自动入账。

## 复用与限制

复用现有金额、日历日期、下载与弹窗，不增加框架。表头与状态风险参考 [china_bean_importers](https://github.com/jiegec/china_bean_importers)，未复制其 Python 业务代码；复式会计输出和退款语义不同，不能直接导入 MoneyTalk。现成完整工具的评估保留在 [调研计划](bill-sync-research-plan.md)。

新增 csv-parse 7.0.3（MIT，无新增运行依赖）与 @zip.js/zip.js 2.22.0（BSD-3-Clause，无新增运行依赖），精确版本和完整许可证随项目提供。使用 ZIP 原生压缩入口，不下载远程 worker、不启用 WASM、不放宽 CSP。2026-10-02 `pnpm audit --prod` 为 0 项已知公告，不能等同于没有风险。

实际构建中核对模块按需加载，gzip 约 23.16 KB；ZIP 模块仅选到 ZIP 时加载，gzip 约 37.39 KB。npm 包解压体积与网页传输体积不同，没有安装整个 Python／Go 记账系统。

每份文件／ZIP 4 MB，本批原件和解压后分别最多 20 MB、最多 40 个文件、20,000 行；每行 16 KB。ZIP 在解压前检查声明大小／数量，流式接收时再次限制实际大小并校验 CRC／AES 校验码，不写出文件路径。未知附件、损坏结构、路径穿越、重复文件名均明确失败；Excel／PDF 原件尚未适配，不能改扩展名冒充 CSV。

报表中的候选消费不包含待核对项；退款、还款是证据金额，不据此计算最终净支出。“观察日期”仅说明文件中有哪些交易，不证明平台已完整覆盖。全部读取失败时金额显示“未取得”，不能显示为零消费。

## 实际验证

13 项专门测试通过，覆盖原生字段、引号逗号、整数分、长交易号、重复与冲突、同日同额两笔、坏日期／坏金额、未知状态、退款、三类还款、字符编码、AES／ZipCrypto、错码／缺码、损坏 ZIP、大小／数量限制、不安全路径、HTML 内容不执行、输出拒绝覆盖及私有文件权限。完整 `pnpm verify` 的检查、33 项测试及构建均通过。

内置 @Browser 后台复用同一标签：先检查开发页 `127.0.0.1:5173/settings`，再在 `127.0.0.1:8787/settings` 验证构建版与生产同样的 CSP。虚构 ZIP 错码明确报错；更换正确码后核对成功：候选消费 1,231.50 元，退款证据 200 元，未拆清还款 245 元；故意坏金额与两笔同额消费保留为异常／待核对。未调用云端写入。

360／390／430／768／1440 px 核对弹窗的页面与内部均无横向溢出。内置浏览器无法回读下载事件后，按全局路由使用 Ego Lite 的独立任务空间“MoneyTalk 历史核对与发布”（11）：实际下载并解析虚构 JSON 报告，金额与只读标识一致；筛选得到 7 笔待核对，关闭后重新打开没有报告和已选文件。没有操作个人 Chrome 或原生 Computer Use。真实 iPhone 键盘、系统文件选择、邮箱附件分享、国内网络仍未验证。

已发布到现有受保护网址：`https://moneytalk-web.550754381zzx.workers.dev/settings`，版本 `0bf64842-0880-4cd0-9549-e3a043fdbec0`。同一 Ego Lite 页面完成线上本人登录态读取、虚构 AES ZIP 解压、金额核对、解压码清空及报告下载回读；未执行任何账目写入或迁移。匿名网页／接口仍跳转 Access。详见 [云端发布记录](cloudflare-deployment.md)。

## 下一道门槛：最少真实样本，不要一开始拿全部历史

默认试验范围为 2026-09-01 至 2026-09-30；分期账单可能跨自然月，按原消费日期核对，不按还款账单标题猜日期。12 个月扩展范围暂定 2025-10 至 2026-09，不是平台已证明可以完整导出的承诺。

1. 支付宝与微信各取得一份官方“个人对账”原件，优先 CSV 或含 CSV 的 ZIP。按 [支付宝教程](https://docs.qianjiapp.com/other/import_guide_alipay_app.html)、[微信教程](https://docs.qianjiapp.com/other/import_guide_weixin.html) 查找；当前 App 菜单仍需本人核实。必要支付验证只能本人操作。
2. 白条、美团月付、抖音月付先各取得一小段原始消费／账单明细，最好同时包含消费、还款本金／费用及退款。若 App 没有导出，先提供脱敏截图或保存的明细页面来确认字段，再选择最省操作的采集路线；不能宣称已验证存在某个导出按钮。
3. 用户仅需提供所选范围原件和对应 ZIP 解压码，或把它们放到项目外专用目录。解压码只用于该批处理，不能提交支付密码、登录密码、Cookie、身份证或邮箱授权码。试验可先脱敏，金额、日期、表头结构保持不变，交易号使用一致替代值以便测去重与关联。
4. 助手核对实际格式与消费覆盖、保存原件、测量用户操作次数、补齐适配和异常测试，再生成真实候选预览。只确认该具体预览的真实写入，不再次询问普通实现／测试是否继续。

目前无法独立完成本人 App 安全验证，也没有授权范围内的真实样本。其余实现和验证持续推进；不为绕过这一门槛索取整箱邮箱权限、猜月付格式或先改变生产账本模型。后续邮箱自动收件需明确独立收件范围，不把 Gmail 标签筛选冒充邮箱级权限隔离。

## 本机离线命令

```sh
pnpm bills:review /absolute/new-review-directory 本人主账号 /absolute/alipay.csv /absolute/wechat.csv
```

输出 `review-report.json`、编号原件副本、`completed.json`，不连接服务、不写入账本。目标父目录须已存在，目标目录不能已存在；项目内部仅允许已忽略的 `web-cloudflare/local-data/` 下新目录。异常退出码 2 表示报告有文件异常，仍需查看清单。CLI 暂不交互询问加密 ZIP 密码；加密包优先使用网页本地解压流程，代码接口可传每份文件的临时解压码。
