# 手机优先打磨计划与验收 · 2026-10-02

## 事实与范围

用户已在真实手机打开网站，登录可用。最新目标：约 70–80% 操作在手机完成；上半屏看内容、下半屏集中操作；确认简洁，保存结果可查；蓝白视觉和桌面深蓝工作台继续沿用。只删除明确测试文字记录，不补猜任何真实日期，不恢复封存的外部账单采集，不新增付费服务。

只读云端核查发现真实订阅保存为 pending 草稿，金额已存但起始月与扣款日仍为空，尚未生成真实支出。用户保存的“持续循环”与原截止月同时存在；旧逻辑忽略截止月，这是需要防止的范围歧义。不能把草稿存云端说成支出已经入账。

## 调研与复用结论

- [Apple 2023 设计奖](https://developer.apple.com/design/awards/2023/)：Flighty 是交互奖获奖应用，学习清晰的重点信息和熟悉的操作方式；不模仿品牌素材、不扩张金融功能。
- [Things 官方功能展示](https://culturedcode.com/things/features/)：常用内容直接展示，附加字段按需展开；底部添加入口保持一致；借鉴其任务导向和明确转场。
- [钱迹主界面官方指南](https://docs.qianjiapp.com/home/index.html)：期间收支、按日分组、记录后即可查见；本期结余不是资产余额。
- [一木官方页面](https://www.yimuapp.com/index.html)：参考文字输入与紧凑金额层级；官网列出的奖项作为产品自述，不当作独立认证。本次不引入它的自动采集、资产及预算模块。
- [Apple Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets)：限定任务、单层弹窗、明确返回／退出、复杂表单可用较高面板；用户要求主要操作在底部，这是网页针对单手使用的布局取舍，不宣称完全复制原生规范。
- [Apple Motion](https://developer.apple.com/design/human-interface-guidelines/motion)：动画解释状态与方向，减少动态效果时取消位移动画。
- [MDN 原生 dialog](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog) 与 [VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)：复用浏览器焦点、模态保护和可见窗口信息，处理键盘缩小可视区域。
- [Vaul 开源抽屉](https://github.com/emilkowalski/vaul)：MIT，但 README 明确说明未维护，且需要 React；为简单原生网页引入整套框架与依赖不合适。只参考底部抽屉模式，复用现有原生 dialog，新增最小样式／焦点逻辑。
- 原项目已有 Chart.js、Lucide、数据接口、确认哈希、幂等保存与会话草稿；全部复用，不新装 UI 库，不将账本发给外部 AI。

## 执行方案

1. 数据可信：将“仅保存草稿”与“已计入账单”分开；缺信息展示精简原因；冲突范围不允许隐式扩大；确认后显示条数、准确金额、实际日期范围和“查看账单”。查询失败不能显示为空，也不能把保存成功隐藏成失败。
2. 手机四页：记账页先展示最近记录／保存结果，下半区域填写和保存；账单上方金额与列表，底部月份与筛选；统计上方收支、图表与排行，底部月份／周期／图表切换；我的上方身份与账本状态，下方分类、导出、备份、回收站操作。记录详情仍可从内容打开，主要编辑／删除／保存置底。
3. 底部面板：常见确认不再长段说明；统一标题、金额、状态、底部主按钮与关闭；文字录入为“输入→核对→入账结果”，只露必要字段，原文／高级项折叠。复用单个 dialog，不堆多层弹窗。
4. 视觉与动态：蓝色操作，绿色已入账，琥珀色待补全，红色错误／删除；颜色配文字与图标；44px 以上主要触控区、16px 输入；200–280ms 转场，减少动态效果停用；底部安全区与键盘可见区域适配。
5. 测试记录：核对明确测试身份与已删除支出后清理测试文字批次；真实订阅候选原样保留；清理前在 Git 外保存可恢复快照。测试用真实线上新数据须标明虚构，完成后清理或移入回收站。

## 测试与验收计划

- 自动数据测试：缺起始月／日期绝不生成；截止月与持续冲突不忽略；按月展开准确、跨月统计对账；重复确认、并发修改、超时同标识重试、删除后不补回、权限及备份恢复。
- 浏览器功能：真实本地接口完成输入、核对、确认、结果、查看账单、刷新、修改删除；故意断网／失败／连点；草稿确认与支出确认各自有不同反馈。
- 布局：360/390/430 手机，768/1440/1920 桌面；四个页面、底部面板、长内容、大金额、展开分类、键盘可视区模拟、页面放大和键盘操作；检查内容未被底栏挡住，横向不溢出。
- 动画与易用性：面板进出和状态变化有明确反馈；减少动态效果有效；主要操作靠下，可聚焦，错误可读；不能只靠颜色传递状态。
- 线上：完整检查和构建后部署同一受保护网址；读取版本与页面、刷新、测试保存读回、统计对账及撤销／清理；真实订阅候选保持未猜测字段。匿名访问仍受保护，不改登录规则。
- 用户最终验收：实际 iPhone Chrome 的键盘、系统日期控件、单手操作舒适度、动画流畅度必须保留为用户验收项；桌面模拟不能冒充真机。用户睡觉期间继续完成其他工作，不为这一步反复催确认。
