# 连续口述与平台续记 · 第二批实施方案

## 目标与当前事实

用户对照消费平台倒序连续报账，希望以后打开网站直接知道上次从哪个商品记到哪个商品，能找到未完成批次、逐条确认、记完再接同平台或换平台。当前金额、月份精度、批次原序、逐项幂等确认、私有分类建议和平台草稿键可复用；不接入新的外部语音/模型服务，不恢复自动采集。

当前批次为最多 100，字数 10000、单批 40 项；读取全批次逐次查询关联账目会扩大查询次数。暂不改变容量上限和备份格式，此轮先改批次查找与续记闭环，并把查询改为固定次数。容量扩展、长文字自动切块仍需要独立备份与真实服务负载验证，不能承诺已支持任意长口述。

## 复用与研究

[Actual 的官方筛选文档](https://actualbudget.org/docs/transactions/filters/)支持“查找条件清晰、筛选可取消”；[钱迹搜索说明](https://docs.qianjiapp.com/url-scheme/search.html)支持以备注内容找记录。复用当前原生输入、按钮、文字批次及 Zod/Worker 权限；原生列表筛选分页无需安装第三方数据表、框架或依赖，不复制竞品素材与代码。

## 实施闭环

1. 文字批次列表提供直接可点的全部/待核对/已记完/暂停状态与平台条件，商品/原文搜索，每页 8 批，显示筛选结果数和明确空态；筛选不修改真实批次。
2. 输入区按选定平台展示最近一批首尾、连续边界/下一项，并能一键继续该待核对批次；不把暂停或删除当成可直接越过。
3. 确认整批后的主按钮明确为“继续淘宝”等，换平台选项直接平铺；沿用各平台会话草稿，不串平台。来源混合时不假定单一平台。
4. 从核对中的“新一批”离开时，若还有未确认内容，先提供“存草稿并继续”与“继续核对”；未保存字段或保存失败保持原内容，不清空；已云端保存且没有新改动时直接继续。草稿只保存候选，0 笔入账。浏览历史时单独保留尚未解析的文字；筛选状态在当前会话恢复。
5. 批次读取改为固定次数查询：批次及关联记录分两次取，再按批次归组；保留权限约束和完整进度。

## 验收

集成：100 批边界、旧批次/关联账目读取、混合来源、暂停/删除与提醒一致、跨账本拒绝、固定查询数量，以及旧备份恢复。

端到端：390/1440 查找条件/分页/零结果/失败重试，旧批次直接续记，整批确认后继续同平台或换平台，各平台草稿隔离，核对途中新批次保存/取消/失败/重试，刷新恢复和断网不重复入账。保留现有全部用例，执行完整 pnpm verify:release。额外覆盖响应到达时按住导航再松开，导航节点不能被刷新拆走；键盘焦点和选中页面要一致。

本地截图直接内嵌在聊天中，正式上线后核对版本、静态资源和原账本；真实服务测试只用独立合成候选账本，清理后读回。真实 iPhone 与国内网络仍单列未验证。
