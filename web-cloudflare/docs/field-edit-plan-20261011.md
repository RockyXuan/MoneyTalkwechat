# 账单四字段直接编辑计划 · 2026-10-11

目标：统计最近账单与完整账单列表里的日期、备注、分类、金额，一次点击打开对应的简洁编辑面板，手机轻触同样可用。铅笔／分类图标仍保留整条详情入口。

复用：两处桌面表格共用 tableRows；移动列表共用 recordRow；复用 entryForm、原生 dialog、现有 PATCH、版本冲突、重复提交标识和服务器权限。未引入新依赖或迁移。先核对项目现有编辑实现，再复核 [MDN dialog](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog) 的聚焦和关闭方式、[W3C 表单反馈](https://www.w3.org/WAI/tutorials/forms/notifications/) 的就近提示；原生能力足够，无需额外表格或弹窗组件。

## 行为与边界

- 点哪个字段，只呈现该字段。日期保留“只记月份／精确到日”；分类显示同收支类型的全部可用分类；备注支持清空；金额不使用负号表示支出。
- 首次打开从服务器读取最新记录，保存始终包含完整其他字段与版本，避免只改金额清空备注。服务器确认后显示保存结果，刷新列表、统计及批次摘要。
- 取消／Esc 未修改直接关闭；有未保存修改时保留原有放弃提示。错误与重试显示在保存按钮上方；并发冲突显式重新载入最新记录，不覆盖其他设备。
- 桌面小面板；手机底部面板，查看在上、操作在下，44px 触控、输入至少16px、沿用键盘与安全区适配。支持键盘、减少动效偏好。
- 不更改已确认账目的历史日期，不改用户草稿，不自行补齐 iCloud 起始月或真实扣款日。

## 分阶段与验收

1. 实现共用字段入口与紧凑表单；检查桌面两入口、移动列表与记账页最近记录。
2. 集成测试：逐字段修改后另外三项原样保留；统计／导出／读取一致；旧版本不得覆盖。
3. Chromium 与 WebKit 端到端：四字段保存、刷新、跨月、只记月、清空备注、非法金额、并发冲突、断网结果不明与重试、取消、键盘与布局。跑完整 verify:release 和控制覆盖。
4. 固定合成数据截图，内置浏览器核对布局；部署后验证云端资产、保护边界及独立候选账本的可逆写／读／清理。真实数据前后核对，不激活测试账本。
5. 用户验收：正常网址上点四字段，观察只出现对应选项，保存后金额／分类／日期／备注及统计一致。真机键盘和国内网络须单独标明验证状态。
