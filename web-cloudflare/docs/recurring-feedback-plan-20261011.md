# 循环记账：可省略扣款日与确认旁反馈

用户反馈：旧循环草稿的扣款日未知时不能确认；提示在顶部，滚动到绿色按钮后看不到原因。目标是让操作处同时告诉用户缺什么、如何处理，不增加新的确认步骤。

## 实现与复用

- 沿用现有 `date_precision=month`、`YYYY-MM` 保存和统计、逐项确认、版本控制与同标识重试。无需新字段、迁移、依赖或第三方服务。
- 精确日模式的循环项在确认旁提供“不填扣款日，按月记”。点击仅更改当前候选的精度并清空扣款日，不自动保存账目。需要具体日时可切回并自行填写；已生成的规则继续锁定。
- 确认旁直接显示本项缺失字段；扣款日缺失时同时说明可填 1–31 日或选择月份。选择按月记不免除起始月、截止范围、金额、分类及其他真实疑问。
- 输入错误、重复消费、服务失败和冲突反馈也留在本项操作处，保留原顶部状态用于兼容现有流程。字段修正后移除过时错误。支持键盘焦点和文字提示，不只靠红色说明问题。
- 复用原生按钮、已有绿色操作风格与 CSS，无动画/表单库引入。W3C 的[错误识别](https://www.w3.org/WAI/WCAG22/Understanding/error-identification.html)及[修正建议](https://www.w3.org/WAI/WCAG22/Understanding/error-suggestion.html)要求文字说明错误及可行修正；本项目按用户要求选择确认处作为主要反馈位置。这不是对整个网站 WCAG 合规性的声明。

## 验收与发布

新增 API 集成及两引擎 E2E 用例覆盖旧草稿、手机/桌面视野、月精度持久化、四个月写入、未知起始月拒绝、非法日/金额和服务失败重试。运行完整 `pnpm verify:release`，通过后才部署。线上仅用独立候选测试账本核对受影响流程并清理，实际用户草稿不改写。生产发布与真机边界另记实际验收结果，方案不代表已通过。
