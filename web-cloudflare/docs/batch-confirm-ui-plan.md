# 逐条确认与月份记账（2026-10-10）

## 用户目标与交付范围

用户对照购物 App 连续口述，在网站逐条确认；下次可从购买记录的断点继续。手机操作占多数，电脑保留信息广度。本次重用现有文字批次、幂等提交、记录版本、Worker/D1、原生 dialog 和 Chart.js，无新增依赖、付费资源或认证权限。

- 每条绿色确认按钮只保存该项；循环项按钮标明实际展开条数。服务器确认后才显示绿色已保存，再向右淡出、收拢空间，下一项获得焦点。失败保留卡片与输入；结果不明使用同一提交标识核对、重试。
- 桌面宽度至少 1100px 时为固定右栏（460px）、独立滚动，不遮罩、不锁页面；主工作区保留可操作内容。较窄屏幕使用原有底部面板，跨断点保留同一批次和输入。普通动效约 400ms；减少动态效果偏好下直接更新状态。
- 首页及批次列表持续展示来源、原始顺序的首末产品、确认进度、实际记录时间和下一未确认项。跳着确认显示缺口，连续进度不会跨过未确认项。删除账目保留已处理标识并注明删除数量，避免重新生成。
- 单笔未提供日期默认当前月份；明确月份按该月、明确日/昨天按日。月份/日期可切换，切到日时要求选日，不自动填 1 号。循环未说明日时可按月展开，起始月份及补记范围仍须明确；已有草稿不批量改写。

## 日期与数据一致性

数据库实际保存 YYYY-MM 或 YYYY-MM-DD，查询覆盖所选范围涉及的月份；对不完整日范围明确提示包含具体日期未知的月份记录。日统计额外列“日期未指定”桶，绝不计入 1 号；折线把未知日画成独立点，不串成连续日期趋势。月/季/年汇总、柱/线/饼和金额列表使用同一完整服务端统计。CSV 保留原日期精度。月份账目及带显式精度字段的新规则使用 v3 备份；v1/v2 保持兼容，较早客户端不支持 v3 时应拒绝而不能降格日期。恢复到独立候选账本再切换。

## 复用与规范依据

现有原生浏览器能力足够完成面板及动效，无需动画库。原生非模态 dialog.show() 允许工作区互动，手机使用 showModal()。焦点、Escape、禁止保存中重复操作和减少动态效果按公开规范检查：

- [HTML dialog 与模态行为](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-dialog-element)
- [WAI 对话框焦点规则及示例](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)
- [APG 开源示例，W3C 软件许可证](https://github.com/w3c/aria-practices)
- [prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)

未复制第三方品牌/素材；继续沿用当前锁定依赖。具体图表逻辑只补充月份桶，不更换图表组件。
