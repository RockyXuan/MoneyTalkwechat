# 记账小程序 — 收集箱 & 微信公众号上线计划

## 概述

将现有"待确认记录"升级为"收集箱"，增加来源标签（公众号/小程序）；完成微信公众号从注册到上线的全流程配置，让用户可以在微信聊天中发消息记账，并在公众号菜单中一键进入小程序。平台：mobile。

## 技术方案

| 维度 | 选择 | 理由 |
|------|------|------|
| 公众号类型 | 个人订阅号 | 免费，支持消息接收+自动回复+菜单跳小程序，满足记账场景 |
| 收集箱实现 | index 页面内升级 | 已有5个TabBar，不再新增；优化现有 pending 区域即可 |
| 来源标记 | 复用 pending_records.source 字段 | DB已有 source 列(默认'wechat_oa')，小程序端新增'mini_program' |
| 公众号入口 | 自定义菜单跳小程序 | 个人订阅号支持，无需服务号 |

## 功能模块

### 模块一：收集箱升级（前端）

**职责**：将 index 页面的"待确认记录"区域重构为"收集箱"，增加来源标签和批量操作。

数据结构示例（pending_record，DB已有）：
```json
{
  "id": "uuid",
  "user_id": "default_user",
  "source": "wechat_oa",       // wechat_oa | mini_program
  "raw_text": "早饭20 中饭30",
  "record_type": "expense",    // expense | subscription
  "parsed_data": { "note": "早饭", "amount": 20, "category": "餐饮" },
  "status": "pending",
  "created_at": "2026-01-01T08:00:00Z"
}
```

要点：
- 标题改为"收集箱"，显示未确认数量 Badge
- 每条记录显示来源图标：📱小程序 / 💬公众号
- 解析成功的记录显示摘要（分类+金额），解析失败的显示原文
- 新增批量操作："全部确认"、"全部清除"
- 空状态提示："暂无待确认记录，可通过公众号发消息或在此输入记账"

### 模块二：来源标记（后端）

**职责**：小程序端解析结果保存时标记来源为 mini_program。

要点：
- `POST /api/wechat/pending-records` 新增接口，或复用现有 createPendingRecord
- 前端"记一笔"解析后，若用户未点确认而是保存到收集箱，调用此接口 source='mini_program'
- 目前"记一笔"页面解析后直接确认保存，不经过收集箱。保持此逻辑不变——收集箱仅接收公众号来源的待确认记录和小程序端主动"暂存"的记录

### 模块三：微信公众号上线（配置指南）

**职责**：从零到跑通的全流程操作指南，无需写代码。

步骤：
1. 注册个人订阅号（mp.weixin.qq.com）
2. 开启开发者模式，配置 Webhook URL 和 Token
3. 关联小程序（输入 AppID wxa8ec50265729065c）
4. 设置自定义菜单（菜单跳小程序 pages/index/index）
5. 测试消息收发

##### @page(/) 记一笔

**核心职责**：输入文字AI记账 + 管理收集箱中的待确认记录
**访问路径**：TabBar 首页直达
**布局**：顶部输入区(Textarea+发送按钮) → 收集箱区域(可折叠，含Badge计数) → AI解析结果列表 → 底部操作栏(确认记账/清空) → 编辑弹窗(底部弹出)

**列表项字段**（收集箱记录）：来源图标 / 摘要文本 / 金额 / 分类 / 创建时间

**状态**：
- 空态(收集箱)："暂无待确认记录，可通过公众号发消息或在此输入记账"
- 空态(输入)："说点什么开始记账吧"
- 加载态：Skeleton 占位
